# 客户签约后的交付流程

这份文档用于客户看完 demo、签订合同后，把 demo 转换成客户专用系统。

## 一、签约前确认

- 客户公司或店铺名称
- 行业类型
- 使用场景
- 必须功能
- 可后续追加的功能
- 希望上线时间
- 预算范围
- 付款方式
- 维护方式

## 二、复制客户项目

不要直接在 demo 上改成客户正式系统。应该复制出客户专用项目。

建议命名：

```text
client-{customer-name}-izakaya
client-{customer-name}-usedcars
client-{customer-name}-recycle
client-{customer-name}-realestate
```

复制后保留 demo 仓库继续用于销售演示。

## 三、客户版本定制

客户项目中需要替换：

- 公司/店铺名称
- Logo 和颜色
- 联系方式
- 地址和营业时间
- 菜单、商品、服务项目
- 桌台、车辆、回收品类、房源等业务数据
- 支付方式
- 管理员入口
- 正式网址

## 四、上线前检查

- 手机显示是否正常
- 电脑和平板显示是否正常
- 主要业务流程是否跑通
- 管理后台能否配置关键数据
- 数据是否会误清空
- 客户员工是否能看懂操作
- 是否需要账号登录
- 是否需要云端数据库
- 是否需要打印机、支付接口或外部服务

## 五、交付步骤

1. 创建客户专用项目。
2. 导入客户数据。
3. 本地测试。
4. 给客户演示客户版本。
5. 根据反馈调整。
6. 部署正式网址。
7. 店内培训。
8. 试运行 1 到 2 天。
9. 正式上线。
10. 进入维护阶段。

## 六、维护建议

正式交付后建议设置月维护费，覆盖：

- 小范围文案和菜单修改
- 问题排查
- 数据备份
- 小功能调整
- 系统更新

大型新增功能单独报价。
