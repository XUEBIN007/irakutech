# 居楽テック 演示指南

这份文档用于带着 MacBook、手机或 iPad 去商家现场演示。当前系统是静态演示版，数据保存在浏览器本地，适合说明点菜流程、厨房接单、收银结账和后台管理方式。

## 现场准备

- MacBook 打开厨房、会计、后台三个页面。
- 手机扫码或直接打开顾客点菜地址。
- 如果商家 Wi-Fi 不稳定，使用手机热点。
- 演示前在后台点击“重置演示数据”，避免上一次演示数据干扰。

## 推荐演示流程

1. 顾客坐到 3 号桌，用手机打开点菜页。
2. 顾客选择菜品，提交订单。
3. 顾客继续追加点单，确认“已点订单”和“当前消费金额”会更新。
4. 厨房页看到新订单，点击进入“制作中”。
5. 厨房完成后点击“完成”，订单进入“已完成/等待结账”。
6. 会计页选择桌号，确认未结账订单和应收金额。
7. 选择支付方式，例如 PayPay 或现金。
8. 输入实收金额，确认找零。
9. 点击完成结账，桌台清空，收款记录出现。
10. 后台页展示菜单编辑、桌台二维码、二维码停用和重新生成。

## 外卖・自取演示流程

1. 打开外卖・自取页面。
2. 选择到店自取或店铺配送。
3. 填写姓名、电话和希望时间。
4. 添加菜品并提交订单。
5. 顾客看到订单确认卡、订单号、取餐方式、希望时间和合计金额。
6. 厨房页看到店外订单。
7. 会计页选择店外订单并完成收款。

## 顾客视角说明

顾客扫码后进入对应桌号的点菜页，可以选择菜品、填写备注、提交订单。提交后购物车清空，但“已点订单”会保留本桌未结账订单，顾客可以继续追加点单并看到当前消费金额。

## 商家视角说明

厨房人员打开厨房页即可看到三栏看板：新订单、制作中、已完成。会计人员打开会计页，按桌号结账，记录现金、PayPay、LINE Pay、微信支付、支付宝、信用卡或其他 QR 支付。

后台可以管理菜单和桌台二维码。停用某个桌台二维码后，顾客再扫码会看到不可用提示。重新生成二维码后，旧二维码失效，新二维码可继续使用。

## 常见问题

### 这个演示地址以后会变吗？

演示地址可以长期使用。真正给客户交付时，通常会给客户设置独立网址，例如客户自己的域名或专用 GitHub Pages/服务器地址。

### 现在能直接给真实商家用吗？

当前版本适合演示和小范围试用。正式商用前建议增加云端数据库、管理员登录、订单同步、数据备份、权限管理和真实支付接口。

### 支付接口已经接入了吗？

当前只记录支付方式和收款金额，没有接入 PayPay、LINE Pay、信用卡等真实支付接口。这样适合先演示流程，后续可以按商家需求接入。

### 商家需要什么硬件？

最低配置是顾客手机扫码点菜，厨房使用一台平板或电脑，会计使用一台电脑或平板。正式商用可增加小票打印机、厨房打印机、收银钱箱和稳定网络。

## 购买后的交付流程

1. 确认店铺名称、菜单、桌台数量、语言需求和支付方式。
2. 建立客户专用版本和演示确认环境。
3. 导入菜单、价格、分类和桌台二维码。
4. 配置正式网址或客户域名。
5. 在店内贴二维码并培训店员。
6. 试运行 1 到 2 天，修正菜单、动线和结账细节。
7. 正式上线，并约定维护方式。

## 报价说明建议

演示阶段可以先说明这是可定制系统。正式报价可拆成三部分：

- 初期设置费: 菜单录入、桌台二维码、店铺配置、上线培训。
- 月维护费: 小修改、数据备份、问题处理、功能维护。
- 追加开发费: 真实支付接口、打印机、库存、会员、预约、报表等扩展功能。
